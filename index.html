Salesforce integration API

Create meetings and completed sales activities in Counterpoint. Start with sandbox access, then use the Event or Task JSON below.

API access & bearer token

SANDBOX Base URL — append an endpoint path below:

https://c.cpfunds.com:3002/api/integrations/salesforce

Get your token

  1. Jeff supplies a private, expiring, one-time secret link. The link is delivered separately from this public documentation.
  2. Obtain the link’s passphrase from Jeff through a separate channel. Open the link, enter the passphrase, and reveal the API key once.
  3. Save the key in Salesforce’s secure credential configuration. If the link has expired or was already opened, ask Jeff for a new handoff.

The API key is your bearer token. No login or token-exchange request is needed. Use the sandbox key only with the sandbox API; production access is supplied separately.

Request headers

Authorization: Bearer <YOUR_API_KEY>
Content-Type: application/json

Send Authorization on every request and Content-Type on POST requests. Replace <YOUR_API_KEY> with the secret key, not the retrieval link or passphrase.

Check access

GET /v1/health

{
  "status": "ok",
  "api_version": "1",
  "environment": "test"
}

Health confirms authentication and configuration. It does not check database or Outlook readiness.

Sandbox inputs

Use wsname: "Jeff" (case-insensitive) and fictional advisor ID "2147483000", "2147483001", or "2147483002". Replace sample Salesforce IDs with your own 18-character IDs. Generate and save a UUID v4 request_id for each new operation.

Create Event

Find a record / check delivery

GET /v1/events/by-salesforce/{salesforce_record_id}

GET /v1/tasks/by-salesforce/{salesforce_record_id}

Use the same bearer token. No request body. Returns the linked record’s IDs and current status; the reused field is omitted.

For Events, pending means Outlook delivery is queued; synced confirms delivery and linkage. action_required, outlook_deleted, or cancelled requires reconciliation. A successful create does not mean Outlook delivery has finished.

Retries & errors

Save the request before sending. Retry with the same request ID, Salesforce record ID, and payload after a timeout or lost response. A successful replay returns 200, the original Counterpoint ID, and reused: true. JSON property order and wsname capitalization do not matter.

Changed content or a new request ID for an already-linked Salesforce record returns 409 SOURCE_CONFLICT. Reconcile using lookup. Do not generate new IDs to bypass a conflict. A lookup 404 does not prove an in-flight create failed.

Error JSON — example

{
  "error": {
    "code": "INVALID_FIELD",
    "message": "Supply an IANA timezone.",
    "field": "timezone",
    "retryable": false
  },
  "correlation_id": "6d97dbf9-47b5-4a85-9b23-e5fd45308fab"
}

Correct 400/401/403/422 requests before resending. For 429, respect Retry-After. For timeouts and retryable server errors, use bounded exponential backoff and keep the original request identity. Retain correlation IDs for support.
